# OneAtlas

AI model discovery and intelligence platform: browse, search, filter, compare and rank AI models across labs and providers.

**Live:** https://oneatlas-beige.vercel.app/models
**Role:** Full Stack Engineer

> All model, price and benchmark data is **sample data** generated by a seed script for this demo. Model names are real, but specs, prices and scores are illustrative.

## Features

- **Discovery:** search, filter by lab / provider / type / capabilities / open weights / 1M+ context, sort by price, context window, release date or name, paginated, table and card views
- **Model detail:** specs, modalities, capabilities, all providers with prices, benchmark scores, related models
- **Comparison:** 2 to 4 models side by side, best value highlighted, shareable URL
- **Rankings:** overall, per-category and per-benchmark leaderboards
- **Labs and providers:** directories with detail pages (lab releases, provider-supported models and prices)
- **Global search** in the navbar (Ctrl+K), responsive layout, loading / error / empty states

## Tech stack

Next.js (App Router), React, TypeScript, Tailwind CSS, Next.js API Routes, PostgreSQL (Neon), Prisma 6, Zod, deployed on Vercel.

## Architecture

```
Postgres (Neon) -> Prisma -> Next.js API routes (/api/*) -> React pages
```

The frontend never imports data directly; every page fetches from the API.

### Data model

Lab, Provider, Model, ModelProvider (per-provider pricing), Benchmark, BenchmarkScore.

### API

| Endpoint | Purpose |
|---|---|
| `GET /api/models` | Search, filter, sort, paginate |
| `GET /api/models/[slug]` | Model detail |
| `GET /api/compare?models=a,b,c` | Side-by-side comparison |
| `GET /api/rankings` | Leaderboards (`benchmark`, `category`, `limit`) |
| `GET /api/labs`, `/api/labs/[slug]` | Lab directory and detail |
| `GET /api/providers`, `/api/providers/[slug]` | Provider directory and detail |
| `GET /api/search?q=` | Global search |

## Technical decisions

- **Price lives on ModelProvider**, since one model costs different amounts at different providers.
- **Denormalized `lowestInputPrice` / `lowestOutputPrice`** on Model so price sorting is a plain indexed column sort. The seed script keeps them in sync.
- **Zod validation** on every query: bad input returns 400 with a clear message, missing records return 404, and unexpected errors return 500 without leaking details.
- **Indexes** on the filtered and sorted columns, with `id` as a sort tie-breaker so pages never overlap.
- **Rankings averaged in Postgres** with `groupBy`; the response includes how many benchmarks each average covers.
- **Pooled connection for the app, direct connection for migrations** (Neon).
- **Function region set next to the database** to cut latency.

## Running locally

```bash
git clone <repo-url> && cd oneatlas
npm install
```

Create `.env`:

```
DATABASE_URL="<neon pooled connection string>"
DIRECT_URL="<neon direct connection string>"
```

```bash
npx prisma migrate deploy
npx tsx prisma/seed.ts
npm run dev
```

## Known limitations / next steps

- Sample data only; a real ingestion pipeline (for example from a public models API) would replace the seed
- Overall ranking averages whatever scores a model has, so models with fewer scores are compared on fewer benchmarks
- Filters are not yet stored in the URL for the models page
- No authentication, caching layer or automated tests yet
